# Phase 03: Content Differentiation

Timeline from report: Weeks 3-4

## Objective

Make priority pages meaningfully different from generic utility pages. The report says templated "practical uses" and repeated boilerplate are weaker than concrete examples, constraints, privacy behavior, and troubleshooting.

## Source Basis

Drawn from these report sections:

- Executive summary
- On-page SEO
- Current-tool opportunity map
- Prioritised backlog
- Week-by-week outputs

## Priority Work

1. Rewrite the top 10 PDF pages with unique, tool-specific copy.
2. Rewrite the top 10 developer pages with unique, tool-specific copy.
3. Remove or rewrite repeated generic SEO paragraphs.
4. Add real input-to-output examples.
5. Add implementation-specific limits and constraints.
6. Add privacy behavior per tool.
7. Add troubleshooting based on real tool failures.
8. Add workflow-based internal links.

## Page Content Template

Each priority page should answer:

- What does this tool actually do?
- What input formats, encodings, file sizes, or browser limits matter?
- What stays local in the browser?
- Are any network calls made?
- What is a real example input and output?
- How does the tool work at a practical level?
- What common errors can happen?
- Which related tools help with the next step?
- When was the page last reviewed for accuracy?

## Priority Clusters

PDF priority candidates:

- Merge PDF
- Split PDF
- Compress PDF
- Organize PDF
- JPG to PDF
- PDF to JPG
- OCR PDF
- Redact PDF or Blackout PDF
- PDF Security
- PDF Metadata Remover when built

Developer/Data priority candidates:

- JSON Formatter
- CSV to SQL
- CSV Query
- JWT Decoder
- Regex Tester
- Hash Generator
- Base64 Encoder
- URL Encoder
- Cron Parser
- JSON to TypeScript/Zod when built

## Checks

- Page title targets the exact intent and includes a differentiator where natural.
- H1 is human-readable and specific.
- First paragraph names capability, limits, and privacy behavior.
- Example is real and useful.
- "How it works" describes the actual tool, not generic three-step filler.
- FAQ is unique to the tool.
- Internal links are contextually relevant.
- No fabricated freshness or fake authority claims.
- No content exists only to satisfy a word count.

## Deliverables

- Content rewrite list for the first 20 priority pages.
- Before/after notes for repeated template sections.
- Tool-specific example blocks.
- Privacy and limitations copy for each priority page.
- Updated internal link recommendations.

## Exit Criteria

Move to Phase 04 when:

- The highest-value pages no longer read like interchangeable templates.
- PDF and developer pages clearly show privacy, constraints, and concrete examples.
- Content improvements are tied to Search Console and product priorities.
