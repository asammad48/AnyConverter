What a Parquet file is

Apache Parquet is a columnar, compressed, typed file format used by Spark, Databricks, Snowflake exports, AWS Athena/Glue, BigQuery exports, pandas, Polars, and DuckDB. Because it stores data by column rather than by row, it compresses well and is fast to query — but it isn't human-readable, which is why converting it to CSV is often the fastest way to open it in Excel or a text editor.

Why decimals and big IDs break in other converters

Parquet can store 64-bit integers larger than JavaScript's safe integer range, and DECIMAL columns as scaled integers. A converter that reads these through ordinary floating-point numbers silently corrupts them — a 19-digit ID can come out changed in the last few digits. This tool keeps large integers as exact digit strings instead of routing them through floating-point math.

Opening the CSV in Excel

Excel in Denmark, Spain, and much of Europe expects a semicolon-delimited CSV with a comma as the decimal separator; the US/UK default expects a comma delimiter and a period. This page's Danish and Spanish versions default to the semicolon/comma-decimal/BOM combination that opens correctly without a manual import wizard.

For other structured-data conversions, try CSV to SQL, CSV Query, or the JSON Formatter.

Frequently Asked Questions

Is my Parquet file uploaded? +
No. The file is read directly by your browser and the CSV is created on your device.
Why does my CSV open as one column in Excel? +
Excel in many European regions expects semicolons as the delimiter. The Danish and Spanish versions of this page use semicolons, a comma decimal separator, and a UTF-8 BOM by default.
What happens to nested list or struct columns? +
Lists and structs are written as JSON text in the CSV cell, so the data is preserved and round-trippable even though it is not flattened into separate columns.
Will large numbers and decimals stay exact? +
64-bit integers are converted using exact digit strings rather than floating-point numbers, so large IDs are not rounded.
