# Phase 01 — Visual Origin & Asset Provenance Report

**Project:** AnyConverter Creative Studio — Visual Quality Production Programme  
**Phase:** 01 (Visual Baseline, Canonical Compositor & First Publishable Slice)  
**Document Purpose:** Transparent audit of every visual component's technical origin across all Phase 01 video deliverables, answering the Seventh Independent Audit Truth Gate.

---

## 1. Executive Summary & Plain-Language Provenance

| Question | Honest Technical Answer |
|---|---|
| **Were the visual compositions designed by a user through the UI?** | **No.** The visual scenes (geometries, layouts, camera motions, character rigs, and lighting models) were pre-authored by the engineering team in JavaScript (`reference-shot.js` and `creative-director.js`). |
| **Are the visuals generated by external AI APIs (Midjourney, DALL-E, Stable Diffusion, Runway)?** | **No.** Zero external generative AI models or APIs were used. All visuals are 100% computed client-side in the browser via HTML5 Canvas 2D path primitives. |
| **Are there Blender 3D models or pre-rendered sprite PNGs in the video exports?** | **No.** The character (Mr. Cockatoo), office props, and noir corridor are 100% procedural vector code drawn dynamically onto the canvas on every frame. |
| **What does an ordinary user actually control in Phase 01?** | A user can select among 3 pre-authored visual directions, edit copy (headlines and narrative subheads), customize accent colors, adjust shot frame durations, preview live on canvas, export deterministic WebM video, and save/reopen `.acstudio` project archives. |
| **Is this a general-purpose arbitrary video creation tool today?** | **No.** Phase 01 is an initial **template-based vertical slice**. Arbitrary multi-track sequencing, image/video asset placement into video shots, character design, and custom vector drawing are scheduled for later phases. |

## 2. Component-by-Component Provenance Table

Classification Key:
- **(a) Hard-coded Canvas drawing logic:** Programmed directly into JavaScript canvas drawing routines by engineering.
- **(b) Editable scene object via user UI:** Freely editable by end users via standard public UI controls.
- **(c) User-imported media asset:** External image, video, audio, or 3D asset loaded by the user into the project.
- **(d) Generation model output:** Produced by an AI model, prompt-to-media engine, or third-party service.
- **(e) Verification / Reporting tooling:** External test harness artifacts (Playwright/FFmpeg) not part of the website engine.

## 3. Storage & Asset Packaging Provenance

Inspecting the saved `.acstudio` project archive (`From_Raw_Data_to_Clear_Answers_Master.acstudio`):
```json
{
  "project.json": {
    "version": "1.0",
    "title": "From raw data to clear answers",
    "activeDirection": "cinematic-saas",
    "shots": [ ... 5 shots with headlines, subheads, accentColors, durationFrames ... ],
    "assets": []
  },
  "manifest.json": {
    "format": "acstudio",
    "version": "1.0",
    "assets": []
  }
}
```

**Key Finding:** Both the project `assets` array and manifest `assets` list are empty (`[]`). This confirms that:
1. No external raster images (PNG, JPEG), vector SVG files, or 3D meshes (glTF) are stored in the project archive.
2. The browser renderer reconstructs the visual compositions deterministically using the built-in procedural Canvas code combined with the serialized shot parameters (text copy, accent color, duration).
3. Modifying `project.json` alone allows a user to change headlines, subheads, accent colors, and shot durations, but **cannot** introduce new arbitrary characters, backgrounds, or vector animations without accompanying engine drawing code.
